# Resume Board

여러 프로젝트의 `HANDOFF.md`와 Git 상태를 한곳에서 확인하는 로컬 대시보드입니다. 중단했던 작업의 목표, 진행 상황, 다음 할 일과 실행 명령을 빠르게 찾아볼 수 있습니다.

## 빠른 시작

**필수:** Linux 또는 macOS, Python 3.10 이상. 외부 Python 패키지나 API 키, 빌드 과정은 필요하지 않습니다. Git 정보를 보려면 Git도 설치되어 있어야 합니다.

```bash
git clone https://github.com/utf-404/resume-board.git
cd resume-board
./start.sh
```

브라우저에서 **http://127.0.0.1:8765** 에 접속합니다. 종료하려면 터미널에서 `Ctrl+C`를 누르세요.

다른 포트를 사용하려면:

```bash
./start.sh --port 8766
```

## 사용법

1. **프로젝트 등록**에서 프로젝트 폴더의 절대 경로 또는 `~/projects/my-project` 같은 홈 경로를 입력합니다.
2. 프로젝트를 선택해 작업 개요, **인계 기록** 원문, **Git 변경사항**을 확인합니다.
3. 실행 명령은 **복사**한 뒤 터미널에서 직접 실행합니다.
4. 파일이나 Git 상태가 바뀌면 **새로고침**을 누릅니다.

`HANDOFF.md`나 Git 저장소가 없는 폴더도 등록할 수 있습니다. 등록 해제는 목록에서만 제거하며 실제 파일은 삭제하지 않습니다. **폴더 열기**는 Linux의 `xdg-open`이 있는 환경에서 사용할 수 있습니다.

## HANDOFF.md 작성

### 에이전트에 작성 규칙 전달하기

`AGENTS.md`는 에이전트의 작업 지침이고, `HANDOFF.md`는 프로젝트의 작업 상태를 기록하는 파일입니다.

작성자의 `AGENTS.md`에서 작업 인계 규칙을 정리한 [AGENTS.md 참고 예시](docs/AGENTS.example.md)를 제공합니다. 대상 프로젝트의 `AGENTS.md`에 필요한 내용을 추가하고, 에이전트에게 이 지침에 따라 `HANDOFF.md`를 작성·갱신하도록 요청하세요. 기존 지침이 있다면 필요한 규칙만 병합합니다.

예를 들어 다음과 같이 요청할 수 있습니다.

> AGENTS.md의 작업 인계 규칙을 읽고, 현재 프로젝트의 파일과 Git 상태를 확인한 뒤 HANDOFF.md를 작성해줘.

이 예시는 작업 인계에 필요한 규칙만 담고 있습니다. Resume Board가 지침을 자동 설치하거나 인계 파일을 생성하지는 않습니다.

### 인계 파일 예시

등록할 프로젝트 폴더 바로 안에 `HANDOFF.md`를 만드세요. 다음 예시의 제목을 사용하면 대시보드에서 항목별로 요약합니다.

````markdown
# 작업 인계

## 작업 목표와 완료 조건
- 로그인 화면 구현 및 동작 확인

## 완료한 작업과 변경 파일
- 기본 레이아웃 작성: app.py

## 주요 결정과 이유
- 기존 화면 구조를 유지해 변경 범위를 줄임

## 실행한 검증과 결과
- 단위 테스트 통과
- 브라우저 동작 확인은 아직 미실시

## 진행 중인 부분
- 입력값 검증 구현

## 남은 작업 순서
- [ ] 입력값 검증 완료
- [ ] 브라우저에서 동작 확인

## 다음 실행 명령
```bash
python3 app.py
```

## 막힌 사항
- 없음
````

- 명령은 코드 블록 또는 단독 인라인 코드로 작성합니다. 대시보드는 명령을 자동 실행하지 않습니다.
- 남은 작업의 `[x]` 항목은 완료 목록으로 분류합니다. 남은 작업이 없으면 `없음`을 적으세요. 기록이 없으면 **미기록**으로 표시합니다.
- `주요 결정과 이유`, `실행한 검증과 결과`도 기록할 수 있으며, 원문은 **인계 기록**에서 확인할 수 있습니다.
- 기록을 누적할 때는 `## 새 목표: ...`로 구분합니다. 마지막 목표를 기준으로 요약하며, 전체 기록은 원문에 남습니다.

요약은 Markdown 제목을 읽는 규칙 기반 처리입니다. 중요한 상태는 해당 제목 아래 명시하고 필요하면 원문을 확인하세요. 부모·하위 폴더의 인계 파일은 자동으로 읽지 않으며, `AGENTS.md`와 같은 에이전트 지침 파일은 별도로 설정해야 합니다.

## 데이터와 제한

- 등록 목록은 `.data/projects.json`에 저장되며 Git에서 제외됩니다. 다른 컴퓨터에서는 프로젝트를 다시 등록해야 합니다.
- 프로젝트 파일과 Git 상태를 읽으며, 프로젝트 내용이나 인계 기록을 수정하지 않습니다.
- 로컬 단일 사용자용으로 루프백 주소에서만 실행합니다. 로그인, 클라우드 동기화, 작업 자동 실행 기능은 없습니다.
- 파일 잠금에 POSIX의 `fcntl`을 사용하므로 Windows 네이티브 실행은 지원하지 않습니다.
