# Resume Board

프로젝트별 `HANDOFF.md`와 Git 상태를 읽어, 중단했던 개발 작업을 이어갈 수 있게 돕는 로컬 대시보드입니다. 목표·진행 상황·다음 할 일·실행 명령을 한눈에 확인합니다.

## 실행

Python 3.10 이상이 필요합니다. Git 상태 조회에는 Git이, Linux 파일 관리자 열기에는 `xdg-open`이 필요합니다. 외부 Python 패키지, API 키, 빌드 과정은 없습니다.

저장소를 내려받은 상위 폴더에서 실행합니다. 이미 저장소 폴더 안이라면 `./start.sh`만 실행하세요.

```bash
cd resume-board
./start.sh
```

브라우저에서 **http://127.0.0.1:8765** 에 접속하세요. 종료는 실행 터미널에서 `Ctrl+C`입니다. 포트가 사용 중이면 `./start.sh --port 8766`으로 실행합니다. 다른 위치에 clone했다면 해당 폴더에서 동일하게 실행하면 됩니다.

## AGENTS.md와 HANDOFF.md의 역할

| 파일 | 역할 | 위치와 기준 |
| --- | --- | --- |
| 전역 `AGENTS.md` | 에이전트가 따르는 공통 작업·인계 규칙 | `~/.codex/AGENTS.md` (사용자 홈 기준) |
| Isaac 프로젝트의 `HANDOFF.md` | Isaac 작업 목표, 진행 상황, 검증, 남은 작업 | `./HANDOFF.md` (`isaac_usd` 폴더 기준) |
| Resume Board의 `HANDOFF.md` | 이 대시보드 개발 작업의 인계 기록 | `./HANDOFF.md` (`resume-board` 폴더 기준) |
| 다른 프로젝트의 `HANDOFF.md` | 각 프로젝트의 독립적인 작업 상태 | `./HANDOFF.md` (각 프로젝트 폴더 기준) |

문서의 `./`는 명시된 프로젝트 폴더를, `~`는 현재 사용자의 홈 폴더를 뜻합니다. 위 경로는 프로그램에 고정된 조회 경로가 아닙니다. 정확한 파일 이름은 **`AGENTS.md`**, **`HANDOFF.md`**입니다. Linux에서는 대소문자도 구분합니다.

- **작업 지침은 전역으로, 작업 상태는 프로젝트별로 관리합니다.** 홈의 `HANDOFF.md` 하나로 모든 프로젝트를 묶지 않습니다.
- Isaac 프로젝트를 Resume Board 폴더 안으로 옮길 필요가 없습니다. 기존 위치를 그대로 등록합니다.
- 대시보드는 **등록한 폴더 바로 안의 `HANDOFF.md`**를 읽습니다. 부모 폴더의 인계 파일로 대체하거나 하위 폴더를 재귀 탐색하지 않습니다.
- 예를 들어 `isaac_usd` 폴더를 등록하면 그 안의 `HANDOFF.md`를 읽습니다. Git 저장소가 `origin_Btype_tofu`에만 있다면 루트의 Git 상태로 대신 표시하지 않습니다. 해당 저장소를 별도로 등록하면 Git 정보는 확인할 수 있지만 부모의 인계 기록은 상속하지 않습니다.
- 대시보드는 `AGENTS.md`를 실행하거나 편집하지 않습니다. `AGENTS.md`나 `WORK_STATE.json`에만 있는 할 일을 자동으로 가져오거나 새 작업을 생성하지 않습니다.

## 현재 전역 AGENTS.md에 설정된 작업 규칙

다음은 현재 환경의 지침을 정리한 내용입니다. 이 저장소를 clone하는 것만으로 전역 설정이 설치되거나 변경되지는 않습니다. 전역 원본 파일은 이 저장소에 복사하지 않았습니다.

### 작업 진행과 인계

- 승인된 작업 범위와 완료 조건을 기준으로 끝까지 진행하며 사용자가 지정한 순서와 우선순위를 따릅니다.
- 중요한 단계가 끝나거나, 작업 중단·세션 인계 전에 현재 프로젝트의 `HANDOFF.md`를 갱신합니다. 기존 형식과 유효한 정보를 보존합니다.
- 새 세션이나 컨텍스트 압축 후에는 `HANDOFF.md`, 실제 파일, Git 상태를 함께 확인합니다. 기록과 실제 상태가 다르면 확인된 실제 상태를 기준으로 기록을 바로잡습니다.
- 완료한 작업과 남은 작업을 구분하며 검증하지 않은 결과를 성공으로 기록하지 않습니다. 비밀번호·토큰은 인계 파일에 적지 않습니다.
- 일반적인 구현 선택은 승인 범위 안에서 판단합니다. 사용자 답변이 필요한 경우 이유를 남기고, 답변과 무관한 작업은 계속합니다.

### 자동 실행과 역할 분담

- 장시간 무인 작업이나 새 창 자동 인계를 사용자가 요청했을 때만 `~/.local/bin/codex-auto`와 `~/.codex/codex-auto-guide.md`를 확인해 적용합니다.
- 일반 세션에 자동 실행기가 자동 적용되는 것은 아닙니다. 별도 요청 없이 세션 재시작이나 무한 반복을 구성하지 않습니다. 원본 세션의 모델·추론 강도·권한·승인 정책을 임의로 바꾸지 않습니다.
- 메인 에이전트가 목표·역할 배정·통합·최종 검증·보고를 책임집니다. 독립 작업은 조사/구현/검토 역할로 나누며, 작은 작업이나 순차 작업은 직접 처리합니다.
- 위임 시 목표·맥락·수정 파일·완료 조건·검증 방법을 지정하고 같은 파일을 동시에 수정하지 않습니다. 다른 에이전트의 변경을 되돌리지 않습니다.
- 하위 에이전트는 부모 설정을 따릅니다. 추가 재위임은 메인이 명시적으로 요청한 경우만 허용합니다. 인계 전 하위 작업 결과와 미완료 사항을 정리합니다.

이 규칙은 에이전트의 작업 방식에 관한 설정입니다. Resume Board가 이 규칙을 강제로 적용하거나 작업을 자동 실행하는 기능은 없습니다.

## HANDOFF.md 권장 형식과 화면 반영

| 인계 파일 제목 | 대시보드 반영 |
| --- | --- |
| 작업 목표와 완료 조건 | 이번 작업의 목표 |
| 완료한 작업과 변경 파일 | 완료한 작업 |
| 주요 결정과 이유 | 분류 데이터에 보존, 인계 기록 탭에서 원문 확인 |
| 실행한 검증과 결과 | 분류 데이터에 보존, 인계 기록 탭에서 원문 확인 |
| 진행 중인 부분 | 현재 진행 상황 |
| 남은 작업 순서 / 다음 할 일 | 다음 할 일 및 항목 수 |
| 다음 실행 명령 | 줄바꿈을 유지하는 명령 복사 카드 |
| 막힌 사항 | 확인이 필요한 부분 |

`남은 작업` 안의 `[x]` 항목은 완료 목록에, `[ ]` 항목은 다음 할 일에 표시합니다. 다음 할 일이 비어 있으면 **미기록**으로 표시하며 작업 완료를 의미하지 않습니다. 한국어와 일부 영어 제목을 지원하지만, 아래 표준 형식 사용을 권장합니다.

````markdown
# 프로젝트 작업 인계

## 작업 목표와 완료 조건
- 로그인 화면 구현과 동작 확인

## 완료한 작업과 변경 파일
- 기본 레이아웃 작성: app.py

## 주요 결정과 이유
- 외부 의존성을 줄이기 위해 표준 라이브러리 사용

## 실행한 검증과 결과
- 단위 검사 통과
- 실제 브라우저 검증은 아직 미실시

## 진행 중인 부분
- 입력값 검증 구현 중

## 남은 작업 순서
1. 입력값 검증 완료
2. 브라우저에서 동작 확인

## 다음 실행 명령
```bash
# 공통 작업 폴더에서 해당 프로젝트로 이동
cd my-project
python3 app.py
```

## 막힌 사항
- API 응답 형식 확인 필요
````

### 과거 기록이 누적된 인계 파일

`## 새 목표: ...` 또는 `## 현재 목표: ...`가 있으면 마지막 해당 제목 이전의 작업과 명령은 현재 요약에서 제외합니다. 해당 목표 안에서 분류되지 않은 서술형 하위 제목은 진행 기록으로 보고, 가장 마지막 기록을 현재 진행 상황에 표시합니다. 이전 단계의 할 일과 명령을 현재 실행 대상으로 노출하지 않도록 처리합니다. 전체 문서는 **인계 기록** 탭에서 그대로 확인할 수 있습니다.

요약은 Markdown 제목과 라벨을 읽는 규칙 기반 처리입니다. 서술 속의 모든 조건 변경이나 완료 여부를 의미적으로 통합하지는 않습니다. 현재 할 일과 명령은 표준 제목 아래 명시하고, 누적 기록의 최신 진행 상황과 원문도 함께 확인하세요. 인계 기록이 자동으로 갱신되거나 Git 변경에서 할 일이 자동 생성되지는 않습니다.

## 사용 순서

1. 처음 실행하면 Resume Board 자체가 등록되어 인계 내용을 보여줍니다.
2. **프로젝트 등록**에는 실제 프로젝트 폴더의 절대 경로를 입력합니다. 터미널에서 해당 프로젝트 폴더로 이동한 뒤 `pwd -P`로 확인한 값을 붙여넣으세요. 문서의 상대경로 표기와 달리 등록 입력은 절대 경로 또는 `~/...` 형식을 사용합니다.
3. 왼쪽 목록에서 프로젝트를 선택해 작업 개요를 확인합니다.
4. **인계 기록**에서 원문을, **Git 변경사항**에서 변경 파일·브랜치·마지막 커밋을 확인합니다.
5. 실행 명령의 **복사**를 누른 뒤 터미널에 붙여넣어 실행합니다. 웹에서 명령을 자동 실행하지 않습니다.
6. **폴더 열기**는 서버가 실행되는 컴퓨터의 파일 관리자를 엽니다.
7. `HANDOFF.md`나 Git 상태를 변경한 뒤 **새로고침**을 누르면 최신 내용이 반영됩니다. Python 서버 코드를 수정했다면 서버도 재시작합니다.

`HANDOFF.md`나 Git이 없어도 폴더를 등록할 수 있습니다. 등록 해제는 목록에서만 제거하며 실제 폴더나 파일을 삭제하지 않습니다.

## 저장 위치와 GitHub 업로드 범위

- `.data/projects.json`: 등록한 로컬 프로젝트 목록. 재시작 후 유지되며 Git에서 제외합니다.
- `HANDOFF.md`: Resume Board 개발 인계 기록. 소스와 함께 관리합니다.
- 전역 `AGENTS.md`, 외부 프로젝트의 인계 파일, 사용자 인증 정보는 저장소에 복사하지 않습니다.
- 등록된 프로젝트의 실제 내용은 GitHub로 동기화하지 않습니다. 새 컴퓨터에서 clone하면 해당 컴퓨터의 프로젝트 폴더를 다시 등록해야 합니다.

## 검증과 제한

```bash
python3 -m unittest -v
```

현재 백엔드 테스트 9개가 통과했습니다. 등록/해제와 영속성, Git 상태, 표준 인계 형식, 누적 목표 처리, 잘못된 입력 및 경로 접근 등을 검증합니다. HTTP 응답과 JavaScript 구문도 확인했습니다. 브라우저 제어 연결 제한으로 실제 화면·클릭·클립보드·파일 관리자 동작은 아직 GUI에서 검증하지 못했습니다.

로컬 단일 사용자용 초안이며 127.0.0.1에서만 실행합니다. 로그인·클라우드 동기화 기능은 없습니다. 프로그램을 실행하는 컴퓨터의 파일을 읽으므로 같은 컴퓨터의 브라우저에서 접속하세요.
